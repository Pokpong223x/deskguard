# DeskGuard

## รุ่นเตรียมใช้งาน 1.0.1 — 2 พฤศจิกายน 2026

ใช้ Node.js 24 และติดตั้ง dependency ตาม lockfile:

```powershell
npm ci
npm run verify
npm start
```

`npm start` เปิด Expo Go สำหรับทดสอบบนโทรศัพท์ ส่วน `npm run start:dev` ใช้กับแอป development build ที่ติดตั้งไว้แล้ว

ทดลองบนคอมพิวเตอร์ด้วย `npm run web` หรือสร้างเว็บด้วย `npm run export:web` แล้วเปิดด้วย `npm run preview` ที่ http://127.0.0.1:4173 เว็บใช้โหมดตัวอย่าง ไม่ตรวจจับเซนเซอร์มือถือจริง และต้องเปิดผ่าน HTTP แทนการดับเบิลคลิก `index.html`

รุ่นนี้ป้องกันการเริ่มเฝ้าระวังระหว่างบันทึก PIN/การตั้งค่า เพิ่มชุดทดสอบการเขียนข้อมูลและตัวเปิดเว็บ และเพิ่ม CI ตรวจ TypeScript, tests และ export ทั้งเว็บ/iOS ดูขอบเขตผลตรวจล่าสุดใน [docs/RELEASE-1.0.1.md](docs/RELEASE-1.0.1.md)

การ export iOS สร้างเฉพาะ JavaScript bundle หากต้องการติดตั้งเป็นแอป iPhone ต้อง build IPA และเซ็นก่อนติดตั้งตามขั้นตอนด้านล่าง รุ่นนี้ยังต้องเปิดแอปและหน้าจอไว้ระหว่างเฝ้าระวัง

แอปโปรเจคเซนเซอร์สำหรับ iPhone: วางเครื่อง เปิดเฝ้าระวัง และส่งเสียงเตือนเมื่อมีการขยับเกินเกณฑ์ ใช้ **Accelerometer และ Gyroscope จริง** ผ่าน Expo Sensors พร้อมกราฟการเคลื่อนไหว ประวัติเหตุการณ์ และการยืนยันด้วย Face ID, Touch ID หรือรหัสเครื่องเพื่อหยุดเฝ้าระวัง มี PIN ของแอปเป็นอีกทางเลือก

เขียนด้วย React Native + TypeScript + Expo SDK 57 ทดสอบเซนเซอร์และการยืนยันด้วยรหัสเครื่องหรือ PIN ของแอปผ่าน Expo Go ที่รองรับ SDK เดียวกันได้ ส่วน Face ID ต้องติดตั้งแอป DeskGuard ที่ build แยก

## เริ่มใช้งานบน iPhone

1. ติดตั้ง Node.js 24 บนคอมพิวเตอร์ และใช้ Expo Go ที่รองรับ SDK 57 บน iPhone (iOS 16.4 ขึ้นไป) หากยังไม่มี Expo Go รุ่นนี้: รุ่นใน App Store รองรับถึง SDK 54 และการสร้าง Expo Go สำหรับ SDK 57 ผ่าน TestFlight ต้องมีสมาชิก Apple Developer Program ตาม [เอกสาร Expo](https://docs.expo.dev/troubleshooting/expo-go-version-mismatch/) หรือใช้ IPA ที่ build แยกตามขั้นตอนด้านล่าง
2. เปิด Terminal ในโฟลเดอร์โปรเจค แล้วรัน:

   ```powershell
   npm install
   npx expo login
   npx expo start --go
   ```

3. ลงชื่อเข้าใช้ Expo Go บน iPhone ด้วย **บัญชี Expo เดียวกับ Expo CLI** ตามข้อกำหนดปัจจุบันของ Expo Go สำหรับเครื่อง iOS จริง
4. ให้ iPhone และคอมพิวเตอร์อยู่บน Wi-Fi วงเดียวกัน แล้วใช้ Camera บน iPhone สแกน QR code ที่แสดงใน Terminal และเลือกเปิดใน Expo Go
5. อนุญาตการเข้าถึงการเคลื่อนไหวเมื่อระบบถาม ตรวจวิธียืนยันตัวตนของเครื่องในหน้าตั้งค่า หรือตั้ง PIN ของแอป แล้วลองเฝ้าระวังบนโต๊ะที่นิ่ง

ถ้าสแกนแล้วเชื่อมต่อไม่ได้ ให้ตรวจว่า Windows Firewall อนุญาต Node.js บนเครือข่ายส่วนตัว และเครือข่ายไม่ได้แยกการเชื่อมต่อของแต่ละอุปกรณ์ หลีกเลี่ยง Wi-Fi สาธารณะที่บล็อกการเชื่อมต่อภายใน

SDK 57 ถูกเลือกตาม [คู่มือสร้างโปรเจค Expo](https://docs.expo.dev/get-started/create-a-project/) สำหรับ Expo Go บนเครื่องจริงในช่วงเปลี่ยนผ่าน SDK 58 ตรวจเวอร์ชัน Expo Go ให้ตรงกับ SDK ของโปรเจคก่อนอัปเกรดแพ็กเกจ

### ติดตั้งรุ่นที่ใช้ Face ID ได้

Expo Go ไม่รองรับ Face ID บน iOS แต่ใช้ **รหัสเครื่องผ่านหน้าต่างของระบบ** ได้เมื่อโทรศัพท์ตั้งรหัสล็อกไว้ หน้าตั้งค่าจะแสดง “รหัสเครื่อง” พร้อมข้อจำกัด Face ID โดยไม่แสดงว่าใช้สแกนหน้าได้ ต้องติดตั้ง DeskGuard ที่ build แยกเพื่อใช้ Face ID ตาม [เอกสาร Expo LocalAuthentication](https://docs.expo.dev/versions/v57.0.0/sdk/local-authentication/)

โปรเจคเชื่อมกับ [@ppmb/deskguard บน EAS](https://expo.dev/accounts/ppmb/projects/deskguard) และเตรียมสิทธิ์ Face ID แล้ว มีสองวิธีติดตั้งบน iPhone จาก Windows:

#### Sideloadly กับ Apple Account ฟรี

โปรไฟล์ `sideload` ใช้ custom build ใน `.eas/build/ios-unsigned.yml` สร้าง Release สำหรับ iPhone จริงโดยไม่ลงนาม ผ่าน `ios.withoutCredentials: true` จึงไม่ต้องใช้ `eas device:create` หรือทีม Apple Developer แบบเสียเงินในขั้น build:

```powershell
npx eas-cli@27.2.0 build --platform ios --profile sideload
```

เมื่อ build สำเร็จ ดาวน์โหลด build artifacts แล้วแตกไฟล์เพื่อหา `DeskGuard-unsigned.ipa` พร้อม `build-info.json` และ checksum ไฟล์ IPA นี้ต้องให้ [Sideloadly](https://sideloadly.io/) เซ็นก่อนติดตั้ง ไม่ใช่ไฟล์ที่เปิดจาก Safari เพื่อติดตั้งได้โดยตรง รุ่นนี้ฝัง JavaScript และ assets แล้ว ไม่ต้องต่อ Metro เมื่อเปิดแอป

1. ติดตั้ง Sideloadly สำหรับ Windows จากเว็บไซต์ทางการ และทำตามข้อกำหนด iTunes/iCloud บนหน้านั้น
2. ต่อ iPhone ด้วย USB และยืนยัน Trust บนเครื่องเมื่อระบบขอ
3. เลือก iPhone และลาก `DeskGuard-unsigned.ipa` เข้า Sideloadly
4. ลงชื่อเข้าใช้ Apple Account และยืนยันรหัสใน Sideloadly ด้วยตัวเอง แล้วกด Start
5. ทำขั้นตอน Trust developer profile และ Developer Mode บน iPhone ตามที่ iOS แจ้ง แล้วเปิด DeskGuard
6. เริ่มเฝ้า ขยับเครื่องให้เตือน แล้วใช้ Face ID หรือรหัสเครื่องเพื่อหยุดเตือน ลองยกเลิกการยืนยันด้วยเพื่อให้แน่ใจว่ารอบยังไม่จบ

Apple Account ฟรีมีอายุการเซ็น 7 วัน ต้อง refresh/เซ็นและติดตั้งใหม่ตามข้อจำกัดของ Apple; Sideloadly มี auto-refresh ให้ตั้งค่า การสร้าง IPA ผ่าน EAS ใช้โควตา build ของบัญชี Expo และไม่จำเป็นต้องซื้อ Apple Developer Program สำหรับวิธีนี้ ต้องรอผล native build และการติดตั้งบนเครื่องจริงก่อนยืนยันว่า Face ID ใช้ได้ครบ

อ้างอิง: [EAS custom builds](https://docs.expo.dev/custom-builds/get-started/), [withoutCredentials](https://docs.expo.dev/eas/json/), [Sideloadly และบัญชีฟรี](https://sideloadly.io/)

#### EAS internal distribution กับสมาชิก Apple Developer Program แบบเสียเงิน

โปรไฟล์ `preview` ใน `eas.json` สร้างแอปทดสอบที่มีโค้ดและไฟล์ประกอบอยู่ในแอป เปิดใช้งานบน iPhone ได้โดยไม่ต้องต่อ Metro ส่วน `development` ใช้สำหรับแก้โค้ดพร้อม dev server บน Windows สามารถให้ [EAS Build สร้าง iOS ในคลาวด์](https://docs.expo.dev/build/internal-distribution/) โดยไม่ต้องติดตั้ง Xcode:

```powershell
npm install
npx eas-cli device:create
npx eas-cli build --platform ios --profile preview
```

ขั้นตอนนี้ต้องใช้บัญชี Expo และ Apple Developer Program สำหรับเซ็นแอป เลือก Website ใน `device:create` แล้วเปิดลิงก์บน iPhone เพื่อลงทะเบียนเครื่องก่อน build ต้องเลือกเครื่องนั้นให้รวมอยู่ใน provisioning profile จึงติดตั้งได้ เมื่อ build สำเร็จ เปิดลิงก์ติดตั้งบน iPhone แล้วทดสอบ Face ID ใน DeskGuard โดยตรง

หากต้องการรุ่นสำหรับแก้โค้ด ให้ใช้:

```powershell
npx eas-cli build --platform ios --profile development
npm run start:dev
```

รุ่น `development` เชื่อมต่อ dev server ผ่านแอป DeskGuard ที่ติดตั้งไว้ การมีโปรไฟล์และการเชื่อมโปรเจค EAS ยังไม่แปลว่ามี IPA สำเร็จ ต้องตรวจสถานะ Finished และลิงก์ติดตั้งในหน้า Builds ก่อน

## ฟีเจอร์

- UI ตามคลิปอ้างอิง: พื้นขาว หัวข้อดำ การ์ดพาสเทลเลื่อนได้ และมาสคอต 3 ตัว พร้อมปุ่มพักการเลื่อน
- ปุ่มเริ่ม/หยุดเฝ้าระวังอยู่ด้านล่างจอ และการ์ดหยุดเลื่อนอัตโนมัติขณะเฝ้า
- นับถอยหลังก่อนเฝ้าระวัง เพื่อให้มีเวลาวางเครื่อง
- ใช้ Accelerometer ตรวจการเคลื่อนไหว และ Gyroscope ช่วยตรวจการหมุน
- ปรับความไวได้ 3 ระดับ
- กราฟการเคลื่อนไหวแบบสดและสถานะเซนเซอร์
- เสียงเตือนเมื่อค่าการเคลื่อนไหวเกินเกณฑ์ต่อเนื่อง
- ใช้ Face ID, Touch ID หรือรหัสเครื่องผ่านหน้าต่างของระบบเพื่อหยุดเฝ้าระวังและเสียงเตือน
- ตั้ง PIN ของ DeskGuard เพิ่มได้ หรือใช้ PIN นี้เมื่อการยืนยันของเครื่องไม่พร้อม
- โหมดหน้าจอมืดขณะเฝ้า โดยจอยังเปิดและแอปยังอยู่ด้านหน้า
- เก็บการตั้งค่าและประวัติไว้ในเครื่อง
- เลือกไฟล์เสียงหรือวิดีโอ MP4 จาก Files แยกเฉพาะเสียงไว้แจ้งเตือน พร้อมฟังตัวอย่างและกลับไปใช้เสียงเริ่มต้นได้

## เพิ่มเสียงแจ้งเตือนของตัวเอง

1. เปิด **ตั้งค่า → เสียงแจ้งเตือนของฉัน → เลือกเสียงหรือวิดีโอ**
2. เลือกไฟล์ **MP3, M4A, WAV, AAC หรือวิดีโอ MP4 ขนาดไม่เกิน 10 MB** จากแอป Files บน iPhone ถ้าวิดีโออยู่ใน Photos ให้แชร์และเลือก **บันทึกไปยังแอปไฟล์** ก่อน
3. เมื่อบันทึกสำเร็จ กด **ฟังตัวอย่าง** เพื่อตรวจระดับเสียง ตัวอย่างหยุดเองภายใน 10 วินาที หรือกดหยุดฟังได้
4. เปิดสวิตช์ **เสียงเตือน** แล้วเริ่มเฝ้าระวังตามปกติ เมื่อพบการขยับ แอปจะวนเล่นไฟล์ที่เลือกไว้จนยืนยันตัวตนเพื่อหยุด หรือจนการเฝ้าถูกขัดจังหวะจากการออกจากแอป

เมื่อเลือก MP4 แอปจะแยกแทร็กเสียง AAC ออกเป็นไฟล์ M4A เช่น `clip.mp4` → `clip.m4a` และบันทึกเฉพาะเสียงโดยไม่มีภาพวิดีโอ หน้าตั้งค่าจะแสดงป้าย **เสียงจากวิดีโอ** พร้อมชื่อไฟล์ต้นฉบับ การแยกเสียงทำบนอุปกรณ์ ไม่อัปโหลดวิดีโอไปยังเซิร์ฟเวอร์

รองรับวิดีโอ **MP4 ที่มีแทร็กเสียง AAC** เท่านั้น ไม่ใช่ทุกไฟล์วิดีโอ หากไม่มีเสียง ใช้รูปแบบเสียงอื่น หรือไฟล์เสีย แอปจะแจ้งปัญหาและคงเสียงเดิมไว้ โดยไม่แทนที่ด้วยไฟล์ที่ใช้ไม่ได้

เปลี่ยนไฟล์ได้ด้วยปุ่ม **เปลี่ยนไฟล์** และกลับมาใช้เสียงของแอปด้วย **ใช้เสียงเริ่มต้น** ต้องหยุดเฝ้าระวังก่อนเปลี่ยนหรือทดลองเสียง การยกเลิกเลือกไฟล์หรือเลือกไฟล์ที่ใช้ไม่ได้จะคงเสียงเดิมไว้

เลือกเสียงได้ครั้งละหนึ่งไฟล์ แอปคัดลอกไฟล์ไว้ในพื้นที่ของแอปบน iPhone จึงยังใช้ได้หลังเปิดแอปใหม่ ส่วนพรีวิวเว็บเก็บไฟล์ในเบราว์เซอร์ ไม่มีการอัปโหลดเสียงไปยังเซิร์ฟเวอร์ หากไฟล์เดิมอ่านไม่ได้ แอปจะแจ้งให้ทราบและใช้เสียง DeskGuard แทน ไฟล์ต้องไม่มี DRM และอุปกรณ์ต้องถอดรหัสเสียงในไฟล์นั้นได้

## ขอบเขตการทำงาน

การตรวจจับทำงาน **ขณะเปิดแอปอยู่ด้านหน้า** และคงหน้าจอให้ตื่นระหว่างเฝ้าระวัง หลังนับถอยหลังและเริ่มเฝ้าแล้ว กด **เปิดหน้าจอมืด** เพื่อใช้หน้าจอสีดำที่ยังแสดงสถานะและปุ่มหยุด จอไม่ได้ดับจริง และการกลับไปหน้าเฝ้าระวังยังคงตรวจจับต่อ

**กดล็อกเครื่องหรือสลับไปแอปอื่นแล้วจะไม่ตรวจจับต่อเนื่อง** เพราะ Core Motion ไม่ได้ให้สิทธิ์แอปรันเบื้องหลังด้วยตัวเอง ตามคำอธิบายของ [Apple DTS](https://developer.apple.com/forums/thread/841001) เมื่อกลับเข้าแอป รอบที่เฝ้าอยู่จะแสดงว่า **ไม่ได้เฝ้า · รอยืนยันจบรอบ** ต้องยืนยันตัวตนเพื่อจบรอบก่อนเริ่มใหม่ แอปไม่เริ่มเฝ้าใหม่อัตโนมัติ และไม่แสดงว่ามีการป้องกันในช่วงที่ไม่ได้อ่านเซนเซอร์

เปิด **ตั้งค่า → ยืนยันตัวตนเพื่อหยุดเฝ้า** เพื่อดูวิธีที่เครื่องรองรับ ถ้ามีการยืนยันของเครื่องพร้อมใช้งาน ไม่จำเป็นต้องตั้ง PIN ของแอปก่อนเริ่ม เมื่อหยุดเฝ้า ให้เลือกวิธีของเครื่อง ระบบจะเป็นผู้สแกนหรือขอรหัสเครื่องในหน้าต่างของระบบ แอปได้รับเพียงผลสำเร็จหรือไม่สำเร็จ ไม่อ่านและไม่เก็บรหัสเครื่องหรือข้อมูลใบหน้า หากตั้ง PIN ของแอปไว้ก็เลือกใช้แทนได้ โดย PIN นี้เป็นคนละรหัสกับรหัสล็อกโทรศัพท์

การยกเลิกหรือยืนยันไม่สำเร็จจะไม่อนุญาตให้จบรอบ หน้าต่างยืนยันของระบบที่ทำให้แอป inactive ชั่วคราวไม่ถือว่าเป็นการปลดล็อก แต่ถ้าแอปเข้าเบื้องหลังจริงระหว่างยืนยัน ผลที่กลับมาภายหลังจะใช้จบรอบไม่ได้ ต้องกลับเข้าแอปแล้วลองยืนยันใหม่

แอปตรวจได้ว่ามีการเคลื่อนไหว แต่ไม่สามารถระบุว่าใครหยิบเครื่อง และไม่ใช่ระบบป้องกันการขโมยที่รับประกันความปลอดภัย การยืนยันตัวตนควบคุมการหยุดภายในแอป ไม่สามารถป้องกันการบังคับปิดแอป ปิดเครื่อง หรือลดระดับเสียงได้

## ทดสอบ

```powershell
npm run typecheck
npm test
npm run export:web
npm run export:ios
```

`export:ios` ตรวจว่ารวม JavaScript และ assets สำหรับ iOS ได้ ไม่ใช่การสร้าง IPA หรือการทดสอบฮาร์ดแวร์จริง

เปิดหน้าพรีวิวบนคอมพิวเตอร์:

```powershell
npm run web
```

พรีวิวเว็บใช้ตรวจหน้าจอและขั้นตอนการใช้งาน การตรวจความแม่นยำของเซนเซอร์ เสียง และพฤติกรรม iOS ต้องทำบน iPhone จริง

รายการตรวจบน iPhone ก่อนนำเสนอ:

1. ตรวจว่าการยืนยันของเครื่องพร้อมใช้งาน หรือตั้ง PIN ของแอป แล้วเริ่มเฝ้าระวัง วางเครื่องนิ่งจนหมดเวลานับถอยหลัง
2. ปล่อยไว้บนโต๊ะนิ่งอย่างน้อย 30 วินาที ตรวจว่าไม่เกิดเสียงเตือนเอง
3. สะกิดเบา ๆ ครั้งเดียว แล้วเทียบกับการหยิบหรือหมุนเครื่องต่อเนื่อง
4. ทดสอบทุกระดับความไว เปรียบเทียบค่าในกราฟและจุดที่เกิดการเตือน
5. ถ้าตั้ง PIN ของแอปไว้ ให้ใส่ผิด: ต้องยังไม่หยุดเฝ้าระวัง จากนั้นใส่ถูก: ต้องหยุดเสียงและกลับสู่สถานะพร้อมเริ่ม
6. ตรวจว่าประวัติเหตุการณ์ยังอยู่หลังปิดและเปิดแอปใหม่
7. ล็อกเครื่องหรือสลับไปแอปอื่นขณะเฝ้าระวัง แล้วกลับมา: ต้องแสดงว่าไม่ได้ตรวจจับและรอยืนยันจบรอบ ต้องยืนยันก่อนเริ่มรอบใหม่ และไม่เริ่มเฝ้าเอง
8. ทดสอบกรณีไม่อนุญาตเซนเซอร์หรือไม่มีข้อมูล: ต้องบอกปัญหาและไม่แสดงสถานะพร้อมเฝ้าระวัง
9. เปิดเสียงในหน้าตั้งค่าแล้วทดลองหยิบเครื่องขณะเฝ้าระวัง เพื่อตรวจระดับเสียงจริงก่อนเดโม
10. เลือกเสียงจาก Files ทั้งในเครื่องและ iCloud Drive ฟังตัวอย่าง แล้วปิดเปิดแอปใหม่ ตรวจว่าชื่อไฟล์และเสียงยังตรงกัน
11. ยกเลิกตัวเลือกไฟล์ ตรวจว่าเซนเซอร์กลับมาพร้อมใช้งานและเสียงเดิมไม่เปลี่ยน จากนั้นทดสอบเสียงที่เลือกกับการเตือนจริง
12. เลือก MP4 ที่มีเสียง AAC จาก Files ตรวจว่าได้ชื่อ `.m4a` พร้อมชื่อวิดีโอต้นฉบับ ฟังตัวอย่าง แล้วปิดเปิดแอปและทดสอบเสียงเตือนจริงอีกครั้ง
13. เลือก MP4 ที่ไม่มีเสียงหรือมีเสียงที่ไม่รองรับ ตรวจว่ามีข้อความอธิบายปัญหาและเสียงที่เลือกก่อนหน้ายังใช้งานได้
14. บน development build ให้หยุดด้วย Face ID/Touch ID สำเร็จ และทดสอบทางเลือกรหัสเครื่องในหน้าต่างของระบบ โดยไม่กรอกรหัสเครื่องลงในช่อง PIN ของ DeskGuard
15. ยกเลิกการสแกนและทดสอบการยืนยันล้มเหลว ตรวจว่ารอบยังไม่จบและยังหยุดได้ด้วยการยืนยันครั้งใหม่หรือ PIN ของแอป หากเสียงถูกระบบพักระหว่างเปิดหน้าต่างยืนยัน ต้องกลับมาเตือนเมื่อกลับเข้าแอปและรอบยังอยู่ในสถานะแจ้งเตือน
16. ระหว่างเปิดหน้าต่างยืนยัน ให้ล็อกเครื่องหรือออกไปแอปอื่น แล้วกลับมา ตรวจว่ารอบแสดงขาดช่วงและผลยืนยันเก่าไม่สามารถจบรอบได้
17. เปิดหน้าจอมืดหลังเริ่มเฝ้า ปล่อยไว้แล้วลองขยับเครื่อง ตรวจว่าเกิดการแจ้งเตือน กดกลับหน้าเฝ้าระวังแล้วต้องยังเฝ้าต่อ และหยุดได้เฉพาะหลังยืนยันตัวตน
18. เปิดด้วย Expo Go บน iPhone รุ่น Face ID ตรวจว่าระบุข้อจำกัด Face ID และใช้ปุ่ม “รหัสเครื่อง” เพื่อยืนยันผ่านหน้าต่างของระบบได้ ส่วนเว็บต้องระบุว่าการยืนยันของเครื่องไม่พร้อมและใช้ PIN ของแอป โดยไม่จำลองผลสแกนสำเร็จ

## แนวทางนำเสนอ

**ปัญหา:** อยากทราบเมื่อโทรศัพท์ที่วางบนโต๊ะถูกขยับ

**อินพุต:** ค่าความเร่งสามแกนและความเร็วเชิงมุมจากเซนเซอร์

**การประมวลผล:** เริ่มปรับค่าฐาน 700 มิลลิวินาที ประมาณแรงโน้มถ่วงด้วย low-pass filter แล้วใช้ค่าความเร่งที่ต่างจากค่าฐานร่วมกับความเร็วเชิงมุม หากอย่างใดอย่างหนึ่งเกินเกณฑ์ต่อเนื่องอย่างน้อย 250 มิลลิวินาที จึงแจ้งเตือน การสะกิดสั้น ๆ จึงไม่จำเป็นต้องทำให้เกิดเสียงเตือน และการขยับช้ามากต่ำกว่าเกณฑ์อาจตรวจไม่พบ

| ความไว  | ความเร่งต่างจากค่าฐาน | ความเร็วเชิงมุม |
| ------- | --------------------: | --------------: |
| ต่ำ     |                0.24 g |      0.65 rad/s |
| ปานกลาง |                0.13 g |      0.35 rad/s |
| สูง     |                0.07 g |      0.18 rad/s |

เมื่อไม่มี Gyroscope แอปยังใช้ Accelerometer ได้ แต่การหมุนรอบแนวแรงโน้มถ่วงจะตรวจได้ไม่แน่นอน ค่าข้างต้นเป็นเกณฑ์เริ่มต้นสำหรับโปรเจค ควรทดลองกับเครื่องและพื้นผิวที่จะใช้จริง

**เอาต์พุต:** กราฟ สถานะ เสียงเตือน และบันทึกเหตุการณ์ในเครื่อง

**สิ่งที่ควรอธิบาย:** ทำไมต้องกรองแรงโน้มถ่วง ทำไมไม่แจ้งเตือนจากทุกตัวอย่างที่เกินเกณฑ์ และข้อจำกัดของเซนเซอร์เมื่อวางบนโต๊ะที่สั่น

PIN บันทึกเป็นค่า SHA-256 ที่ใส่ salt แบบสุ่มใน iOS Keychain ผ่าน Expo SecureStore ไม่เก็บตัวเลข PIN ตรง ๆ ส่วนเว็บเดโมเก็บค่า hash ใน browser storage ประวัติจำกัดไว้ที่ 100 เหตุการณ์ล่าสุด

รุ่นนี้ยังไม่มีหน้ากู้คืน PIN ที่ลืม และ Keychain บน iOS อาจคงอยู่แม้ติดตั้งแอปใหม่ จึงควรจดจำ PIN ที่ตั้งไว้สำหรับการเดโม
